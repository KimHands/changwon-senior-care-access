# 인구 데이터 실측노트 — 수요 분모 교체

기준월 **2026-06**

고정 재현: `python3 03_분석/05_실측_인구데이터.py --month 202606`
(옵션 없이 실행하면 그 시점의 최신월이 잡혀 결과가 달라진다)

## 판정: 교체 가능

`행정동별 장애인 등록 수`(수시·1회성, 2025 장려작 중복)를 `행정동별(통반단위) 성,연령별 주민등록 인구수`로 교체할 수 있다.

| 항목 | 값 |
|---|---|
| 제공기관 | 행정안전부 |
| 관리부서 | 주민과 |
| **갱신주기** | **월간** |
| 이용허락범위 | 이용허락범위제한없음 |
| 포털 최근 수정일 | 2026-07-06 |
| 행정동 수 | 55개 |
| 총인구 | 986,273명 |
| 60세 이상 | 298,225명 (30.2%) |
| 70세 이상 | 130,229명 (13.2%) |

**갱신주기가 월간이다.** 장애인 등록 수의 '수시(1회성)'와 달리 "어느 부서가 어떤 주기로 쓰는가"를 약속할 수 있다 — 심사 배점의 정책 실현 가능성에 직접 걸린다.

## 제약 1 — 65세 이상을 만들 수 없다

연령 컬럼이 `male60AgeNmprCnt` 처럼 **10세 단위**다. 5세 계급이 없으므로 노인복지법 기준인 65세 이상을 정확히 뽑을 수 없다.

→ 고령 정의를 **60세 이상** 또는 **70세 이상** 중 하나로 고정하고 보고서에 이유를 명시한다. 경로당 이용 실태에 가까운 쪽은 70세 이상이고, 수요를 넓게 잡으려면 60세 이상이다.

## 제약 2 — 의료기관은 주소만으로 행정동을 특정할 수 없다

경로당 원본에는 읍면동 컬럼이 있어 행정동이 확정된다. 의료기관 원본에는 없어서 지오코딩 정제주소의 법정동으로 역매핑해야 하는데, **법정동 하나가 여러 행정동에 걸치는 경우가 27건** 있다.

| 대상 | 건수 | 비율 |
|---|---:|---:|
| 경로당 — 행정동 조인 성공 | 1,035 | 100.0% |
| 의료기관 — 법정동 1:1 확정 | 637 | 48.2% |
| 의료기관 — 읍·면 직접 조인 | 127 | 9.6% |
| **의료기관 — 행정동 모호(1:N)** | **558** | **42.2%** |
| 의료기관 — 조인 불가 | 0 | 0.0% |

모호 상위: 성산구 상남동 171건, 마산회원구 합성동 68건, 마산회원구 석전동 42건, 마산회원구 양덕동 40건, 진해구 석동 38건, 성산구 대방동 36건, 마산회원구 회원동 29건, 마산합포구 산호동 20건

### 이 제약을 우회하는 설계

의료기관을 **행정동에 집계하지 않으면 문제가 사라진다.** 접근성 지표를 '행정동별 의료기관 수'가 아니라 **'경로당에서 최근접 의료기관까지의 거리'**로 잡으면,

- 수요 지점 = 경로당 (행정동 확정 · 좌표 확보)
- 공급 지점 = 의료기관 (좌표만 있으면 되고 행정동을 알 필요가 없다)
- 분모 = 행정동별 고령인구 (경로당의 행정동으로 조인 → 100% 성립)

거리 기반 지표가 접근성의 정의에도 더 맞는다. 행정동별 공급 밀도까지 내고 싶다면 행정동 경계 폴리곤을 구해 좌표로 공간조인해야 한다 — 별도 실측 과제다.
